# Decisions

One line per decision the plan left open: date, decision, reason. Newest last.

- 2026-11-16 · The origin is `ssh://git@git.laibe.cc:2222/anthony/grenier.git`; a GitHub mirror comes later. · Same home as the other projects.
- 2026-11-16 · CI is `.forgejo/workflows/ci.yml` on the `home-linux` runner, not GitHub Actions; the GitHub mirror gets no workflow of its own. · The origin is Forgejo, and kestrel runs its CI the same way. Forgejo reads the same workflow syntax.
- 2026-11-16 · Node 22 in `.node-version` and CI, `engines` `>=22.12`. · The plan's LTS; newer Node works for local development.
- 2026-11-16 · Exact versions, a committed lockfile, `--frozen-lockfile` in CI, pnpm's `minimumReleaseAge` of 7 days, install scripts allowed for esbuild only, actions pinned to a commit. · Security rule 10, and a compromised release is usually pulled within days.
- 2026-11-16 · better-sqlite3's node-gyp build is skipped (`ignoredBuiltDependencies`). · Version 13 ships N-API prebuilds for every platform; the build needed a compiler and changed nothing.
- 2026-11-16 · Workspace packages export their TypeScript source (`exports` point at `src/*.ts`); esbuild bundles the CLI, Vitest runs the tests, and Wrangler will bundle the Worker. No per-package build. · One build step per app instead of one per package; `tsc` only typechecks.
- 2026-11-16 · `@grenier/core` and `@grenier/store` run anywhere (Biome's `noNodejsModules` enforces it); Node-only code is in the `@grenier/core/node` and `@grenier/store/sqlite` subpaths. · The same core has to run on Workers in phase 2.
- 2026-11-16 · Biome's `noRestrictedImports` enforces the plan's conventions: Drizzle is used only in `packages/store`, better-sqlite3 is imported only by `packages/store/src/sqlite.ts`, and `packages/*` never import `apps/*`. · A convention that is checked stays true.
- 2026-11-16 · Tests live in a top-level `tests/` (`unit/<package>`, `e2e`, `fixtures`), as in kestrel, and unit tests import packages through their public entries. · One Vitest config, and the tests exercise what other packages see.
- 2026-11-16 · A package is created by the first task that puts code in it: phase 0 has `core`, `store` and `apps/cli`. · Empty packages would be scaffolding with nothing to test.
- 2026-11-16 · `GRENIER_HOME` moves the home directory (default `~/.grenier`) and both files with it; `GRENIER_CONFIG` and `GRENIER_DB` override each file. · One variable for tests and the daemon's own files; the plan's two overrides still work.
- 2026-11-16 · No config file is written on first run: a missing file means defaults. Unknown keys are errors. Budgets have no default (no limit until set). · Defaults can change in a release without stale copies; a typo must not pass silently; spending limits are the user's call.
- 2026-11-16 · `proxy.upstream_anthropic` and `team.url` must be https, or http to a loopback address. · They receive API keys and the team token; local test servers still work.
- 2026-11-16 · The home directory is created 0700 and the database 0600. · It holds usage, answers and later personal data.
- 2026-11-16 · `grenier status` reads the daemon's pid from `<home>/daemon.pid`, which `grenier start` will write. · Needs no network call and no token.
- 2026-11-16 · drizzle-kit writes the migrations from `schema.ts`; our own runner applies them, from SQL files imported as text, recorded in a `schema_migrations` table, all pending ones in one immediate transaction, and refuses a database newer than the build. · Drizzle's better-sqlite3 migrator reads a folder at run time, which the bundled CLI doesn't have; the table works on D1 too (no `PRAGMA user_version`), and two processes starting at once cannot both migrate.
- 2026-11-16 · The schema is the plan's, plus NOT NULL on keys and times, keys on `answer_sources` and `budgets`, indexes, full-text sync triggers, and `answer_sources` deleted with their answer. Times are Unix milliseconds. Tables are not STRICT: Drizzle cannot declare it, and its typed inserts check types instead. · The plan sketched columns; these keep the data consistent.
- 2026-11-16 · `answers` has `seq INTEGER PRIMARY KEY` beside `id TEXT UNIQUE`, and `answers_fts` uses `seq` as its rowid. · An external-content FTS5 index needs a stable integer rowid; VACUUM can renumber an implicit one.
- 2026-11-16 · The first migrations have the phase 1 tables only (`0000_init`, then the hand-written `0001_answers_fts`); the sqlite-vec table waits for the Embedding model decision, the phase 3 tables for phase 3. · Its dimension depends on the model; a shipped migration never changes.
- 2026-11-16 · In phase 0, "built binary" is `apps/cli/dist/grenier.js`, the esbuild bundle run through `bin`, with better-sqlite3 installed beside it. · A single-file executable is the Tauri sidecar's need, in phase 3.
- 2026-11-16 · Every package is `private: true`. · Nothing can be published before the Name decision.
- 2026-11-16 · Releases will work as kestrel's: `nightly.yml` tags `v*` when main has app commits since the last tag, `release.yml` builds and publishes to a public GitHub releases repository, `docs/RELEASE.md` describes it. Added when there is something to ship. · The release path the other projects use.
- 2026-11-16 · The site lives in the laibe repository as a new site (a case in `App\Sites\Site`, `content/grenier/`, the shared `x-product.*` pages), as Kestrel's and ProofTrail's do, instead of a docs site generated from this repository's `docs/`. · One app serves every product's site.
- 2026-11-16 · The store uses Drizzle (0.45, as statim does): the schema is `packages/store/src/schema.ts`, queries are typed, and `pnpm db:generate` writes the SQL. What Drizzle cannot express (FTS5, triggers, sqlite-vec) goes in custom migrations. · One schema for local SQLite and D1, and the same tool as statim. Prisma and TypeORM bring an engine or a runtime that fit Workers badly.
- 2026-11-16 · pnpm overrides `@esbuild-kit/core-utils>esbuild` to 0.25.12. · drizzle-kit loads its config through it, and the esbuild 0.18 it asks for has GHSA-67mh-4wv8-2f99; drizzle-kit works with 0.25.
- 2026-11-16 · Open decisions taken without the owner, on the owner's instruction to finish the plan without stopping; each can be overturned. · The plan's defaults where it gives one, the simplest sound option elsewhere.
- 2026-11-16 · Provider terms: routing Claude Code through a local gateway is documented and supported by Anthropic, with an API key and with a claude.ai login (code.claude.com/docs/en/llm-gateway, "Subscriptions and gateways"). Grenier forwards `Authorization`, `x-api-key` and `anthropic-beta` unchanged, never stores them, and never changes bodies unless an opt-in flag is on. OpenAI: decided in phase 2 with its endpoints. · Anthropic's gateway docs require forwarding those headers and the error bodies unmodified.
- 2026-11-16 · Budget error code: `429` with `x-should-retry: false` and an Anthropic `rate_limit_error` body. · Anthropic's own gateway marks spend-limit 429s that way, and Claude Code then shows the message without retrying (code.claude.com/docs/en/errors, "spend limit reached"); SDK clients honour the header too.
- 2026-11-16 · Indexing cost: record-only in phase 1 (the plan's default); agents record answers and file summaries, nothing is pre-built. · No tokens spent up front.
- 2026-11-16 · A usage row is written for each inference request (`POST …/v1/messages`); `count_tokens`, `/v1/models` and other calls pass through unrecorded. · Only inference is billed; counting `count_tokens` answers as input would inflate the report.
- 2026-11-16 · The proxy asks the upstream for `accept-encoding: identity` and drops hop-by-hop headers and `content-length`/`content-encoding`; every other header and the body pass unchanged. · Usage is read from the bytes as they pass, which needs them uncompressed; the body still reaches the client byte for byte.
- 2026-11-16 · The daemon answers only requests whose `Host` is 127.0.0.1, localhost or [::1] on its port. · A web page can reach 127.0.0.1; checking `Host` stops DNS rebinding from reading answers.
- 2026-11-16 · `grenier run`, `budget set` and `resume` write the shared SQLite file; the daemon reads sessions, budgets and pauses from it at each request (a held request polls every 500 ms). No control API. · No second endpoint to protect with a token, and a change needs no restart.
- 2026-11-16 · Repo budgets are daily, keyed by the repository's directory name (`--repo app=2`), and counted over sessions with that repo's id. `budget set --<limit> off` removes a limit; limits set this way win over `[budgets]` in config.toml. · The plan names repo budgets but no period; a day matches the daily one.
- 2026-11-16 · Loop detection reads tool calls from request bodies (every `tool_use`, and every `tool_result` with `is_error`), deduplicated by id across a session's requests; a session that began before the daemon started has its first request's history marked as seen, not counted. · Each request resends the conversation; this counts each call once and survives a daemon restart.
- 2026-11-16 · `[guards] pause_timeout` (600 s) bounds how long a paused session's request waits; it is then answered with the same no-retry 429. · The plan asks for "an error after a timeout" without a value.
- 2026-11-16 · Fixtures in `tests/fixtures/anthropic` follow the Messages API's documented shapes, written by hand. · Recording real pairs needs a key; the plan forbids live calls in tests.
- 2026-11-16 · Claude Code itself is checked through the daemon by `pnpm test:agents` (tests/agents), run by hand where `claude` is installed, with a dummy key, a throwaway config directory and a local stand-in for the API. CI runs everything else. · CI has no Claude Code; the check needs no real credential.
- 2026-11-16 · Embedding model: Model2Vec's `minishlab/potion-base-8M` (MIT, 256 dimensions, 30 MB), pinned to revision `bf8b056` and checked against each file's SHA-256, run in plain JavaScript with `@huggingface/tokenizers`. Downloaded into `~/.grenier/models` on first use; `[cache] embeddings = "off"` keeps search to full text, which is also the fallback when the model cannot be loaded. · A static model needs no native code: transformers.js would bring onnxruntime-node (300 MB) and sharp. Reworded questions score 0.49–0.83 against 0.02–0.29 for unrelated ones; 1,000 embeddings take 13 ms.
- 2026-11-16 · Question vectors are float32 blobs in `answer_embeddings`, compared by cosine in JavaScript over one repository's answers, instead of a `sqlite-vec` table. · No native extension to load, the same code works over D1 rows in phase 2, and an exact search over a repository's answers takes milliseconds.
- 2026-11-16 · Hybrid search fuses two candidate lists by reciprocal rank: full-text matches (FTS5 with the Porter stemmer, BM25) sharing at least two of the question's terms, and answers whose question has a cosine of 0.45 or more. The best fused answer is returned, or a miss. · Either signal alone can find a rewording; requiring two shared terms or a close vector keeps unrelated questions out.
- 2026-11-16 · An MCP tool `record_summary` writes the summaries `file_summary` and `repo_map` read; a directory's summary is keyed by a hash over its tracked files' paths and blobs. Summaries are refused over 4,000 characters or with a code block over 10 lines (rule 4). · With record-only indexing nothing else would write them.
- 2026-11-16 · `record_answer` replaces an earlier answer to the same question (case and surrounding space ignored) in the same repository, and refuses files outside the repository or missing ones. · A re-recorded stale answer should not leave its old copy behind; a path outside the repository must not be read.
- 2026-11-16 · The MCP tools take `repo` as a path. Over stdio it defaults to the directory the client launched the server in; over HTTP (the daemon's `/mcp`, stateless Streamable HTTP) it is required, and the request needs `Authorization: Bearer` with a token from the `clients` table (tokens stored as SHA-256; `grenier clients add` arrives in phase 3). · The daemon serves every repository; rule 1 asks for a client token.
- 2026-11-16 · `grenier mcp install` writes the user-level config of each client, keeping everything else in it: Claude Code `~/.claude.json` (`mcpServers`, type stdio), Cursor `~/.cursor/mcp.json`, Codex `$CODEX_HOME/config.toml` (its `[mcp_servers.grenier]` table replaced or appended as text, so comments stay), Claude Desktop's `claude_desktop_config.json` where each system keeps it. The command is the absolute path of node and of grenier's script, with any `GRENIER_*` path overrides as env. · GUI apps do not share the shell's PATH; a client must reach the same database as the CLI.
- 2026-11-16 · `grenier cache clear --repo` takes a path to a repository, or the name of one a session ran in. · Answers are keyed by repository id, which names nothing on its own.
- 2026-11-16 · Prompt-cache report: `grenier report --cache` gives each session's share of input written to and read from the prompt cache, and flags "high churn" when three requests in a row were at least half cache writes. `--json` prints any report as JSON. · A first request always writes; three in a row means the prefix keeps changing.
- 2026-11-16 · `[proxy] inject_cache_control` (off by default) adds a top-level `cache_control: {type: "ephemeral"}` (automatic caching) to a Messages request that carries no `cache_control` anywhere, and logs a `request_changed` event each time. · The API's automatic caching needs one field; rule 9 asks for opt-in and a log.
- 2026-11-16 · The benchmark (`bench/`, `pnpm --filter @grenier/bench bench`) clones Hono v4.6.0 and Flask 3.0.3 at pinned commits, asks three questions each through `grenier run -- claude -p` with only Grenier's MCP server and read-only tools, cold then warm, with a Grenier home of its own on port 7789, and reads tokens and cost from `grenier report --json`. An e2e test runs it with a stand-in agent and API. · The plan asks for one command and a Markdown table, run by hand with the user's key.
- 2026-11-16 · The team server keeps answers and summaries in D1 and no vectors: each machine pulls the shared answers into its own cache, computes their vectors with the local model, and searches locally. No Vectorize index. · Search already runs locally, and an answer pulled within a sync interval is a hit; the server stays small and model-free.
- 2026-11-16 · Sync is push-then-pull every `[team] sync_interval` seconds (20) by the daemon, or `grenier team sync`: unshared answers and summaries of shared repositories go up, then what is newer than the last seq comes down. A new answer to a question marks the older ones deleted on the server (tombstones), and clients drop them. When the server cannot be reached, nothing local changes. · Local stays the source of truth while offline, as the plan asks.
- 2026-11-16 · Sharing is opt-in per repository (`grenier team share [--repo]`, `unshare`); `[cache] share_with_team = true` shares every repository with something in the cache. · Rule 3.
- 2026-11-16 · Team budgets are per UTC day: a team-wide limit and a per-member limit, set by admins (`grenier team budget`). One Durable Object per team counts the day's spend as usage arrives; the proxy reads it (cached 15 s) and answers with the same no-retry 429 once a limit is reached. An unreachable team server lets requests through. Usage goes to the server as daily numbers per member, never prompts or keys. · Team members are in several time zones; a team outage must not stop everyone.
- 2026-11-16 · Member tokens are `gt_` and 32 random bytes (base64url), stored as SHA-256; `grenier team deploy` creates the first admin, `grenier team invite` the others; a revoked token gets 401 on its next call. This machine keeps its token in `~/.grenier/team-token` (0600) unless the env var named by `[team] token_env` holds it. · Rule 8.
- 2026-11-16 · `grenier team deploy` runs a pinned `npx --yes wrangler@4.159.0` with `CI=1`: it finds or creates the D1 database, writes `~/.grenier/team-server/wrangler.json` beside the Worker bundle shipped in the CLI's `dist/server`, applies the migrations, deploys, adds the first admin and joins. · One command after `wrangler login`; the Worker matches the CLI's version.
- 2026-11-16 · The dashboard is one page served by the Worker at `/`, reading `/api/dashboard` with an admin token kept in the tab's sessionStorage, rendering with textContent only. · No build step, no third-party script, nothing a member name can inject.
- 2026-11-16 · Rule 4 applies on the team server too: answers and summaries over 4,000 characters or quoting more than 10 lines of code are refused (`unshareable` in `@grenier/core/policy`, the same check as on each machine). · The server must never hold file contents.
- 2026-11-16 · OpenAI-compatible endpoints live under `/openai/` on the same port, forwarded to `[proxy] upstream_openai` (OpenAI, or any compatible API); `grenier run` sets `OPENAI_BASE_URL` to `…/s/<session>/openai/v1` beside `ANTHROPIC_BASE_URL`. Usage comes from Chat Completions bodies (and streams only when the client asked for `include_usage`, which the proxy never adds) and the Responses API's `response.completed`; cached input counts as cache reads. OpenAI models have no price in `prices.toml` and show as unpriced until `[prices]` sets one. · One daemon for every agent; no invented prices.
- 2026-11-16 · Worker tests run in Miniflare 5 (the beta Wrangler 4.159 ships), through its `convertV4MiniflareOptions`, with local D1 and a SQLite-backed Durable Object; one e2e test runs two daemons and two clones against the Worker served by Miniflare. · The plan asks for Wrangler's local D1.
